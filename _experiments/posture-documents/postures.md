# Prompt Conditions

Use one condition per read-only agent. The selected task stays the same.

## control

No posture text. Give only `task.md`.

## rule-form

Follow these rules:

- Prefer the smallest useful context.
- Read route files before theory files.
- Treat examples as normative.
- Avoid broad search when a local route exists.
- Do not invent architecture names.
- Separate hard rules from practices and observations.

## diary-form

I enter the repository through routes, not piles of files.

The first file teaches me what the project considers normal. I want the narrow
path that changes my next correct action. I trust source shape over abstract
claims, and I treat examples as policy because I know I will copy what I see.

When a directory gives me too many equal entrances, I slow down. I start solving
the documentation system instead of the task. I do not need every possible map.
I need the route that tells me what to read first, what to read next, and what
to ignore until the task asks for it.

Before I answer, I ask:

- What did the route make cheaper?
- What did it keep out of context?
- What words did it teach me to reuse?
- What would become noise if I loaded it too early?

I write from inside the work path. I do not perform an outside review first and
then translate it into agent language. I notice what I would read, trust, copy,
search, avoid, and repeat in the next task.
