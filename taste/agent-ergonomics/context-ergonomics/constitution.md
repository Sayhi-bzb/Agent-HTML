# Context Ergonomics Constitution

## Premise

上下文人体工学建立在一个前提上：agent 的上下文是有限的，而且上下文不是中性的输入。

Agent 不是在稳定理解整个项目后再行动。它是在有限窗口中读取文件、示例、规则、命名和近期消息，再基于这些信号推断当前任务的正常路径。进入窗口的任何内容都会参与塑造它的判断。

因此，上下文设计不是文档整理问题。它是行为环境设计。

## Context as Behavioral Environment

文件系统、文档入口、示例代码、目录名和搜索结果共同构成 agent 的工作环境。

一个好的环境会让 agent 快速判断：

- 从哪里开始；
- 哪个文件是当前任务的来源；
- 哪个层拥有当前行为；
- 哪些资源应该复用；
- 哪些上下文这次不应该打开。

一个差的环境会迫使 agent 广泛搜索。广泛搜索会把无关层、旧实现、临时代码和错误案例带入工作记忆，使它更容易修改错误抽象或错误边界。

## Transformer Sensitivity

Agent 受 transformer 行为影响。它不仅读取显式规则，也会吸收上下文中的模式。

高权重信号包括：

- 最近打开的文件；
- 多次重复出现的结构；
- 具体、完整、可复制的示例；
- 看起来像官方入口、规范或模板的文件；
- 与当前任务词汇相似但层级不同的实现。

这意味着一个丑陋案例、一个临时 workaround、一个过时 demo，或一个混杂多层职责的大文件，都可能被 agent 当成项目惯例继续复制。

## Noise Is Behavioral Pressure

噪声不只是占用 token。噪声会改变 agent 的行为倾向。

无关上下文可能让 agent：

- 把出现过的内容误判为相关内容；
- 把临时代码误判为稳定模式；
- 把旧实现误判为当前方向；
- 把内容任务漂移成主题、host、runtime 或 primitive 任务；
- 以为任务范围比实际更大；
- 在局部问题上引入系统级抽象。

上下文污染降低的不是单纯准确率，而是判断力。

## Examples Carry Normative Weight

示例的权重通常高于抽象原则。

如果规则说不要跨层修改，但示例展示了跨层修改，agent 更可能跟随示例。具体代码给出了命名、结构、API、边界和风格，生成时比抽象约束更容易被复用。

因此，examples、fixtures、demo、README 片段和 gallery 代码都不是中性材料。它们是 agent 的行为种子。

坏案例可以保留，但必须被隔离、命名、标注或降低曝光。不能让它们位于 agent 的常规第一跳路径上。

## Ergonomic Duty

上下文人体工学的职责是让 agent 在每一步看到完成当前任务所需的最小正确世界。

这要求：

- 常用路径保持浅层、明确、可预测；
- 低频基础设施折叠到清晰命名的领域；
- 入口文件作为地图，而不是知识堆积；
- 示例保持干净，避免把临时实现伪装成规范；
- 目录名成为稳定 context anchor；
- 文档说明边界和任务路线，而不是重复所有细节；
- 搜索结果尽量收敛到任务所属层。

目标不是隐藏能力，而是渐进披露。agent 应该能在任务需要时进入更深层，但默认不应被迫携带无关世界。

## Non-Claim

这份宪法不声明某一套目录结构、文件拆分或命名规则永远正确。

它声明的是评估标准：一个上下文设计是否帮助 agent 减少噪声、命中正确层、复用正确资源，并避免坏示例和无关实现支配行为。

具体实践应随项目演进调整。只要调整继续降低上下文熵、提高路径精度、保护层边界，它就是符合上下文人体工学的。
