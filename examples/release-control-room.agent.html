页面是否还是强烈像“单栏文章”。 grid 和 split 有没有真的把内容切开。 badge、alert、field 之间的节奏是否一致。 它同时覆盖摘要、状态、表格、交互字段和多种 layout primitive，足够暴露结构 bug， 又不会像完整业务页面那样把问题藏进太多细节里。 先在桌面宽度看整体分区，再缩窄窗口看 reflow。 看 cluster 是否自然换行，而不是突然挤压内容。 看 frame 是否只做边界，不要偷偷重新定义内部结构。 先看摘要和风险判断，适合想快速知道这次重构有没有真正落地的人。 先看下面的 tabs 和 accordion，适合想直接验证 runtime bridge 的人。 先看字段类组件，适合专门找 field composition 视觉 bug 的人。 阶段 动作 结果 第一步 把 `style-ref` 退场，统一到 `profile-ref`。 公开 contract 和运行时状态口径一致了。 第二步 把 globalLayout 和 componentLayout 接进 artifact profile。 layout primitive 有了正式配置来源。 第三步 把 runtime host、gallery、preview 接到同一个 profile 模型。 页面、gallery、构建产物不再各说各话。
layout primitive 已经不是 runtime-template 私藏逻辑。 page 外层仍保留 document/gallery 两种 policy。 人工视觉验收仍然必要，因为 CSS 壳层还可能盖过结构意图。 如果你看到页面仍然明显像传统文档，那通常不是 authoring 写错了，而是外层 shell policy 或 layout projection 还在替页面做额外决定。 split 是否形成两栏，而不是两张卡片顺序堆叠。 grid 是否形成重复面板区，而不是看起来像普通 stack。 switcher 缩窄时是否自然重排，而不是硬挤压。 看 label 和 control 是否分离得奇怪。 看 description 是否突然形成异常缩进或断行。 看 slider、checkbox、switch 是否共享一致的 field 节奏。 看整体宽度是不是被 page shell 强行收窄。 看上下 padding 是否过重，导致布局显得拥挤。 看 frame 是否只是边界组件，而不是二次决定内容结构。
