# Quick Start

agent-html turns semantic `.agent.html` documents into realtime previews and stable, shareable HTML artifacts.

Most users only need this flow:

1. Run `ahtml`
2. Get the writing prompt
3. Write `.agent.html`
4. Start `preview`
5. Export with `build` when needed

## 1. Install the CLI [#install-the-cli]

`@agent-html/ahtml` is published once to npmjs.com. Pick your package manager:

`ahtml` starts the guided entry flow. On first run it prepares the managed runtime under `~/.ahtml`. It does not write `src/`, `components.json`, `vite.config.ts`, or `agent-html.project.json` into the current repository.

## 2. Optional: install the ahtml skill [#install-the-ahtml-skill]

If you use the `skills` CLI with Codex or other agents, install the `ahtml` skill:

```bash
npx skills add Sayhi-bzb/Agent-HTML --skill ahtml
```

## 3. Get the writing prompt [#get-the-writing-prompt]

```bash
ahtml prompt
```

Use the schema output as the source of truth for registered components, allowed props, allowed children, and approved document style config choices.

## 4. Write a document [#write-a-document]

A valid document needs a `<page>` root.

```html title="artifact.agent.html"
<meta-agent profile-ref="report-default" />

<page title="Review">
  <card title="Summary">
    This review is a stable HTML artifact instead of a long Markdown note.
  </card>
</page>
```

## 5. Start realtime preview [#start-realtime-preview]

```bash
ahtml preview artifact.agent.html
```

`preview` validates the source, starts a long-lived runtime session, and refreshes the rendered document as the source changes. It uses the same render path as `build`, but it no longer depends on materializing the build output directory first.

## 6. Build the artifact [#build-the-artifact]

```bash
ahtml build artifact.agent.html
```

`build` validates the document and exports the portable artifact directory for delivery, sharing, or archive.

## 7. Open the artifact profile gallery [#open-the-artifact-profile-gallery]

```bash
ahtml gallery
```

Gallery opens the artifact profile gallery and component gallery workbench. Use it to manage local profile ids, adjust tokens and treatments, and review how the active artifact profile affects component families before later `preview` or `build` runs fall back to that default profile.
