---
title: Architecture
description: Canvas layer model and ownership boundaries.
---

Canvas is organized as an isolated agent workspace topology:

```text
@agent-html/react
  -> headless collaboration protocol

.agent-html/*
  -> agent operating context and reusable resources

.agent-html/artifacts/*
  -> durable artifact composition and content

packages/cli/src/*
  -> dev and guard command entrypoints

packages/cli/src/host/*
  -> sandbox host, inspector, and prompt bridge
```

Each layer owns one decision. The protocol marks stable regions. The
`.agent-html` workspace provides durable context agents can read and reuse.
Artifacts compose those resources into UI. The CLI starts the guard and preview
surface. The host observes and operates on rendered metadata.

## Protocol

`Artifact`, `Block`, and `Action` are headless protocol markers.

They own metadata, anchors, accessibility minimums, and action dispatch.
`Artifact` also owns the readable root container, with layout parameters
configured by Canvas CSS tokens instead of artifact source props. `Block` is
fully protocol-only: it accepts `id`, `title`, and children. It does not own
width, spacing, colors, borders, radius, shadow, cards, panels, grid structure,
or props passthrough.

## Resources

Canvas resources live under `.agent-html`:

```text
AGENTS.md
styles/index.css
styles/tokens/*
styles/content.css
styles/internal/*
ui/*
hooks/*
lib/*
schema/*
data/*
examples/*
artifacts/*
```

Artifacts should consume these resources before adding local one-off helpers.

## Composition

Artifacts decide block content layout explicitly:

```tsx
<Artifact title="Project Brief">
  <Block id="summary" title="Summary">
    <Card>...</Card>
  </Block>
</Artifact>
```

`Block` marks an inspectable region. It is not a card, panel, or section style.
Do not put layout classes on `Block`; put layout inside the block content.

## Host

The host renders artifacts, discovers blocks, displays guard issues, extracts
source targets, and bridges prompts. Host controls use Canvas UI primitives; the
host must not define artifact visual language.

Canvas is Storybook-like only as an isolated preview surface. Its primary value
is making agent-authored output addressable, reviewable, reusable, and
continuously editable through durable source files.
