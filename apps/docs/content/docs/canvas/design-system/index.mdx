---
title: Design System
description: Canvas UI, token, and shadcn consumption rules.
---

Canvas uses local shadcn-derived UI and CSS variables without forking shadcn.

```text
styles/theme.css
  -> semantic token values

styles.css
  -> Tailwind, shadcn CSS, font imports, token bridge, and base styles

ui/*
  -> local visual primitives

artifact files
  -> primitive composition and Canvas semantic classes
```

## CSS Entry Points

`.agent-html/styles/theme.css` owns semantic token values. It defines variables
such as `--background`, `--foreground`, `--card`, `--primary`, `--border`,
`--ring`, `--chart-*`, `--sidebar-*`, `--font-sans-source`,
`--font-heading-source`, `--radius-base`, and the shadcn-compatible `--radius`
for light and dark modes.

`.agent-html/styles.css` is the runtime CSS entrypoint. It imports Tailwind,
shadcn CSS, fonts, and `styles/theme.css`; it also owns `@theme inline`,
`@source`, dark variant wiring, and base styles. It maps semantic variables into
Tailwind tokens; it does not own component structure.

Host inspection chrome, including surface padding, toolbar offsets, status
spacing, sidebar local spacing, prompt output height, block hover highlighting,
and block action placement, uses the same token pipeline. Canvas-specific host
tokens start in `styles/theme.css` and are applied by semantic classes in
`styles.css`.

Artifact root layout also uses this pipeline. Root width, block rhythm,
background, and foreground values are explicit `--canvas-artifact-*` tokens in
`styles/theme.css` and are applied by `.agent-html-artifact` in `styles.css`.

Artifact content composition uses Canvas semantic classes for spacing,
typography, panel padding, panel radius, icon-box size, and grid gap. These
classes are backed by `--canvas-content-*` tokens.

Artifacts do not import CSS files directly. They consume semantic token classes:

```tsx
className="bg-background text-foreground border-border"
```

## UI Primitives

`.agent-html/ui/*` is the only visual primitive layer for Canvas. It is local
source generated from shadcn conventions, but Canvas owns how it is consumed.
Artifacts and host controls should use these primitives before hand-writing
common UI.

Do not create raw primitive buttons, cards, badges, inputs, tables, sidebars, or
dialog controls in artifacts when a local UI primitive exists.

Current Canvas primitives include accordion, alert, badge, button, card, chart,
checkbox, dialog, input, label, popover, scroll-area, select, separator, sheet,
sidebar, skeleton, table, tabs, textarea, and tooltip.

Do not rewrite every local primitive to tokenize all spacing, density, or
typography values. Keep local shadcn-derived primitives low-modification unless
Canvas needs a primitive API, correctness fix, or accessibility fix.

## Scale Discipline

Color, radius, font, host chrome spacing, artifact root layout, and artifact
content scale use the token pipeline. Local shadcn-derived primitives may still
encode their internal spacing and typography as Tailwind utilities.

Font and radius values start in `styles/theme.css` and are mapped in
`styles.css`:

```text
--font-sans-source
  -> --font-sans

--font-heading-source
  -> --font-heading

--radius-base
  -> --radius
  -> --radius-sm/md/lg/xl/2xl/3xl/4xl
```

Artifacts use Canvas semantic classes such as `canvas-stack-md`,
`canvas-content-panel`, `canvas-grid-gap`, `canvas-icon-box-sm`, and
`canvas-text-body` for visual scale. Layout behavior utilities such as `flex`,
`grid`, `min-w-0`, `overflow-hidden`, `flex-wrap`, `shrink-0`, and `truncate`
may stay in artifact code when they express local structure or overflow
behavior.

Artifacts should not use raw palette classes, arbitrary values, decorative
gradients, oversized radius, heavy shadows, custom font families, manual
tracking, or one-off button, card, and table markup.

## Visual Boundary

`Artifact` owns the readable root container. Agents do not pass root layout or
visual props to `Artifact`; update `--canvas-artifact-max-width`,
`--canvas-artifact-block-gap`, `--canvas-artifact-background`, and
`--canvas-artifact-foreground` instead.

`Block` and `Action` remain protocol markers. Block content layout and visual
treatment belong inside blocks through artifact composition and
`.agent-html/ui/*`.
