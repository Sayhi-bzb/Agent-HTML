`.agent-html` is the Canvas workspace: the agent's local operating context.

It is not just configuration. It contains the instructions, reusable resources,
fixtures, examples, and durable work products an agent may read and compose
while writing React artifacts:

```text
.agent-html/AGENTS.md
  -> workspace rules and operating instructions

.agent-html/components.json
  -> shadcn workspace discovery config

.agent-html/tsconfig.json
  -> local TypeScript and editor discovery config

.agent-html/styles/index.css
  -> CSS runtime entrypoint

.agent-html/styles/tokens
  -> semantic token lookup split by feature

.agent-html/styles/content.css
  -> artifact-consumable Canvas semantic class lookup

.agent-html/styles/internal
  -> locked Canvas system chrome and protocol-adjacent styles

.agent-html/theme
  -> host-owned theme preset resources

.agent-html/ui
  -> local visual primitives such as button, card, tabs, dialog, and select

.agent-html/hooks
  -> reusable React behavior

.agent-html/lib
  -> pure helpers and transforms

.agent-html/schema
  -> typed contracts and validation

.agent-html/data
  -> fixtures and local datasets

.agent-html/assets
  -> bundle-time artifact assets imported by artifact source

.agent-html/public
  -> static files served by URL at /__agent-html/public/<path>

.agent-html/examples
  -> canonical examples

.agent-html/artifacts
  -> durable agent-authored work products
```

`components.json` and `tsconfig.json` stay at the workspace root because shadcn,
TypeScript, and editors discover them from there. They are configuration files,
but moving them into a nested config directory would make discovery less
reliable.

The directory gives agents an explicit workspace instead of relying on a single
prompt. Human-readable guidance and agent-consumable assets stay beside the
artifacts they shape.

Use `.agent-html/assets` for files that artifact source imports into the bundle,
such as images or media used by React components. Use `.agent-html/public` for
URL-addressed files that should stay static and be referenced as
`/__agent-html/public/<path>`. Public files are not imported from artifact
source.

## Authoring Contract

Artifacts import protocol from `@agent-html/react` and local resources by
relative path:

```ts
import { Artifact, Block } from "@agent-html/react"

import { Button } from "../ui/button"
import { useFilter } from "../hooks/use-filter"
import { formatDate } from "../lib/format-date"
import { artifactDataSchema } from "../schema/artifact-data"
import rows from "../data/rows.json"
import diagramUrl from "../assets/diagram.svg"
```

Use `Artifact` as the top-level wrapper. It owns the readable root container
and accepts only `title` and children. Root width and block gap are configured
by `--canvas-artifact-*` tokens in `.agent-html/styles/tokens/artifact.css`;
background and foreground follow the shared foundation tokens. Wrap each major
semantic region in `Block`. Use stable, unique, readable, kebab-case block ids.
`Block` is a protocol marker only: use `id`, `title`, and children, and put
layout or visual treatment inside the block content.
The host owns block prompt actions through its inspection overlay; artifact
source does not render action markers.

Artifact content uses Canvas semantic classes backed by `--canvas-content-*`
tokens for spacing, typography, panel padding, panel radius, icon-box size, and
grid gap. Host chrome uses `--canvas-*` host tokens for surface padding,
toolbar offsets, status spacing, sidebar spacing, floating prompt placement,
and block action placement.

Artifact code must not call the filesystem, shell commands, MCP servers, Codex
app-server, or privileged host APIs.
