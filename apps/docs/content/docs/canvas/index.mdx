# Canvas

Canvas governs the isolated React artifact workspace for agents.

App governs the human-facing workspace. Runtime governs the Agent-HTML DSL
pipeline. Canvas governs `.agent-html`, React artifact composition, local
resources, and host inspection.

## Constitution

### Agent Operating Context

Canvas turns a filesystem directory into durable operating context for agents.
Rules, resources, data, examples, and artifacts live in `.agent-html` so agents
can read, compose, revise, and continue work without depending on chat state.

### Isolated Artifact Workbench

Canvas gives agents a bounded place to generate, preview, validate, and revise
React artifacts without importing the app shell or old runtime UI.

### Headless Protocol

`Artifact`, `Block`, and `Action` mark collaboration boundaries. They provide
metadata, host anchors, source extraction anchors, action dispatch,
and accessibility. `Block` is protocol-only: it accepts `id`, `title`, and
children, and does not accept styling or layout props. Protocol markers do not
provide visual treatment.

### Local Resource Consumption

Artifacts consume local workspace resources: UI primitives, hooks, helpers,
schemas, data, examples, and semantic token classes.

### Inspectable Host Boundary

The host discovers artifacts, overlays blocks, extracts source targets, shows
guard issues, and bridges prompts. It observes artifact metadata instead of
owning artifact layout.
