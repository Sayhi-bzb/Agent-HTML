---
title: Workspace Root
description: Directory layout for the AgentHTML filesystem workspace.
---

`AgentHTML/` is the filesystem workspace where the app places Codex. It is the
shared world the app opens and the cwd Codex uses for shell, read, edit, and
write operations.

By default, the root is the app data `AgentHTML` directory. Users may override it
in Codex Connection settings. AgentHTML opens the root during app startup; root
changes take effect after restarting AgentHTML.

```text
AgentHTML/
  AGENTS.md
  .codex/
  .agents/
    skills/
      agent-html/
        SKILL.md
        references/
          prompt-schema.md
          examples.md
          icons.md
          icon-names.txt
        scripts/
          search_icons.py
        agents/
          openai.yaml
  plugins/
  projects/
    {project-id}/
      project.json
      {section-id}/
        section.json
        artifact.agent-html
        AGENTS.md
  .agent-world/
    tmp/
    logs/
```

`projects/` is the user project space. It stores project records, section
records, and section `artifact.agent-html` files. The artifact file is the
durable source for a user-visible section. Agent edits to workspace content
should target:

```text
projects/{project-id}/{section-id}/artifact.agent-html
```

`.agents/skills/agent-html/` is the AgentHTML runtime bridge for Codex. Its
`SKILL.md` is the agent entrypoint. `references/prompt-schema.md` is generated
by AgentHTML from the current enabled component set. The other listed files are
managed skill resources from the app's resource list and are created when
missing.

`.agent-world/` is the AgentHTML internal space. It stores diagnostics,
temporary files, logs, and other app-managed workspace state. Agents should only
edit `.agent-world/` when the task explicitly concerns workspace internals. It
is not the agent-facing runtime contract.

## Codex Layers

The root can also contain Codex-owned configuration layers:

- `AGENTS.md` provides Codex project instructions.
- `.codex/` provides Codex project-scoped config, hooks, and rules.
- `.agents/` may hold repo-scoped skills and plugin marketplace files.
- `plugins/` may hold local plugin packages with `.codex-plugin/plugin.json`.
- `projects/{project-id}/AGENTS.md` and section-level `AGENTS.md` files may
  provide scoped project or section instructions.

AgentHTML manages `.agents/skills/agent-html/` as its runtime bridge. Other
`.agents/` content remains a Codex extension layer.

AgentHTML does not duplicate Codex ownership of these layers. The app starts
Codex in the workspace root; Codex reads trusted project config, project
instructions, skills, plugins, hooks, MCP servers, and rules according to Codex
semantics.
