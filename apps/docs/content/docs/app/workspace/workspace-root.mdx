---
title: Workspace Root
description: Directory layout for the AgentHTML filesystem workspace.
---

The AgentHTML workspace root is the shared filesystem world opened by the app
and used as the Codex cwd.

By default, the root is the app data `AgentHTML` directory. Users may override it
in Codex Connection settings. AgentHTML opens the root during app startup; root
changes take effect after restarting AgentHTML.

```text
AgentHTML/
  AGENTS.md
  .codex/
  .agents/
    skills/
      agent-html/
        SKILL.md
        references/
          prompt-schema.md
          examples.md
          icons.md
        scripts/
          search_icons.py
  plugins/
  projects/
    {project-id}/
      project.json
      {section-id}/
        section.json
        artifact.agent-html
        AGENTS.md
  .agent-world/
    workspace.sqlite3
    tmp/
    logs/
```

`projects/` is the user project space. It stores project records, section
records, and section `artifact.agent-html` files. The artifact file is the
durable source for a section.

`.agent-world/` is the AgentHTML internal space. It stores workspace metadata,
the local workspace database, diagnostics, temporary files, and logs. Agents
should only edit `.agent-world/` when the task explicitly concerns workspace
internals.

`.agents/skills/agent-html/` is the AgentHTML runtime bridge for Codex. Its
`SKILL.md` is the skill entrypoint, and
`references/prompt-schema.md` is generated by AgentHTML from the current enabled
component set. The examples, icons reference, and icon search script are stable
skill resources created when missing.

## Optional Codex Layers

The following entries are optional user configuration layers:

- `AGENTS.md` provides Codex project instructions.
- `.codex/` provides Codex project-scoped config, hooks, and rules.
- `.agents/` may hold repo-scoped skills and plugin marketplace files.
- `plugins/` may hold local plugin packages with `.codex-plugin/plugin.json`.
- `projects/{project-id}/AGENTS.md` and section-level `AGENTS.md` files may
  provide scoped project or section instructions.

AgentHTML does not duplicate Codex ownership of these layers. The app starts
Codex in the workspace root; Codex reads trusted project config, project
instructions, skills, plugins, hooks, MCP servers, and rules according to Codex
semantics.
